## 1. 관리자 계정 2개로 (`3f93a63`)

**문제** — 비밀번호 재설정 메일이 `wemustgo@mustgokorea.com` 한 곳으로만 갔고, 그 메일함에 접근할 수 없었습니다.

**확인한 제약** — Supabase 는 A 계정의 재설정 메일을 B 주소로 보낼 수 없습니다(수신자·참조 옵션 없음). 그래서 "메일을 공유받기"가 아니라 **두 번째 계정**으로 풀었습니다.

- `ADMIN_EMAILS` 목록으로 바꾸고 로그인 화면에 계정 선택 상자 추가
- 결제 내역 RLS 허용 목록도 두 주소로 확장 (`db/payments.sql`, `db/payments_kr.sql`)
- 주소 하나가 동작하려면 **세 곳**(코드 목록 / Supabase Users / RLS)에 모두 있어야 함 — 한 곳만 빠지면 증상이 각각 다름. `docs/admin-password-reset.md` 에 정리

## 2. 관광지 페이지 (`5a39b0e`, `e3b55f6`)

원페이지로는 검색어 하나에 페이지 하나를 줄 수 없어 광고 효과가 희석되던 문제입니다.

- **서울·부산·제주 45곳**, 각각 한국어·영어
- 페이지마다: 소개 3단락, 운영시간·휴관일·입장료·권장 시간, **대형버스/밴 각각의 접근 조건**, 의전 설계 포인트, 사진(출처 표기), 견적 CTA
- 운영 정보는 2026-10 기준 확인값이고 페이지에 기준일을 표기

**구조** — `src/data/cities/<city>.js` 하나가 출처이고, 라우트·프리렌더·sitemap·홈 버튼이 모두 거기서 생성됩니다. 도시를 늘릴 때 **데이터 파일 1개 + `attractions.js` 3줄**이면 되고 페이지 컴포넌트는 건드리지 않습니다.

**차량 조건이 이 페이지들의 차별점입니다.** 우도는 전세버스 반입 불가, 감천·흰여울은 마을 안 진입 금지, 태종대는 순환로 진입 불가, 남산은 정상 차량 불가 → 환승. 일반 관광 정보에 없고 의전 일정의 성패를 가르는 내용입니다.

## 3. 배포가 세 번 막혔던 일 (`dd04631`, `c0b498d`)

**증상** — 푸시해도 라이브가 바뀌지 않음. 로컬 빌드는 통과.

**원인** — 프리렌더 단계가 헤드리스 크롬을 띄웠는데, Vercel 빌드 컨테이너에서 크롬이 실행되지 않아 **빌드 전체가 죽었습니다.** 샌드박스 플래그(`dd04631`)로도 해결되지 않았습니다.

**해결** — 브라우저를 아예 걷어내고 Node 에서 `react-dom/server` 로 렌더하도록 바꿨습니다(`c0b498d`). 이를 위해 `<head>` 정보를 컴포넌트의 부수효과에서 꺼내 `src/data/seo.js` 로 옮겼고, 브라우저와 빌드가 **같은 서술자**를 씁니다.

> 교훈: 빌드에 브라우저를 다시 들이지 말 것. CLAUDE.md 에 이유와 함께 적어뒀습니다.

## 4. 정본 주소 www 통일 (`825a472`)

`mustgokorea.co.kr` 은 308로 `www` 를 가리키기만 하는데, 코드는 canonical·hreflang·OG·sitemap·robots 를 전부 **non-www** 로 선언하고 있었습니다. 색인 자체는 구글이 리다이렉트를 따라가 www 로 잡지만, **hreflang 이 리다이렉트 주소를 가리키면 무시될 수 있어** 한/영 연결이 깨질 위험이 있었습니다. 다섯 파일의 호스트를 www 로 맞췄습니다.

URL·리다이렉트·콘텐츠는 그대로라 검색 히스토리에는 영향이 없습니다.
